the whole thing is one loop: build the prompt, stream the model, run what it asks for, hand back the results, repeat. everything below is what makes that loop safe to leave running.
• the loop is 371 lines and locked. a test rejects any change to it. everything else plugs in around it: model providers, interfaces, tools, guardrails, policy. adding one is a single file and one line to register it.
• tool calls run in parallel, results land in order. the model can fire off three reads at once and the transcript still reads top to bottom. the scheduler underneath was ported from a trading engine; it does not drop or reorder anything.
• the guardrails have names and reasons. a command allowlist, a retry limit, an approval gate, output limits, a holding area for new plugins, a sandbox for background workers. when rig says no, it says why, so the model fixes its approach instead of thrashing.
• memory is on purpose. nothing sneaks into your prompt on its own. the model saves a fact, recalls it when it needs it, and replaces it when it learns better. tasks, memory, and schedules belong to the repo. a prompt that stays stable is where the cache number comes from.
• every behavior is one sentence in specs/ with a test that holds it there. the exact bytes sent to the model are pinned too. spec first, then the failing test, then the code.
• one binary, nothing else to install. the terminal UI, the scripting CLI, background workers, and a phone-sized dashboard all read the same files on disk. close the laptop; resume from the phone.
rig is built by models running inside rig. this page is the tool they use to do it.
for: anyone running a local model who wants a real agent under it, not a chat window. anyone who wants to read the loop before trusting it. not: a framework, a cloud, a wrapper.

── the surface ────────────────────────
eighteen tools built in. each one small enough that a local model can actually use it well.
bashrun real commands; output comes back trimmed to what matters
fileread · write · edit; an edit is refused if the file changed since you last read it
fsls · find · grep; simple enough for a local model to get right the first time
diffwhat changed since HEAD, or since the last time you looked
pythona live python kernel; your variables survive between calls
websearch and fetch, with a guard against reaching into your private network
todoa task list the model keeps for itself, with dependencies checked up front
remmemory on purpose; save a fact, recall it when needed, update it later, per repo
schedulercron jobs that run a worker in a sandbox while you sleep
delegatehand a task to a fresh worker and get back its answer
pluginrun a plugin, or read what it does, without pausing the main loop
pluginslist · create · delete · reload; anything the model writes waits in pending until you approve it
sessionsbrowse past sessions and live vitals: which models ran, what failed, the cache ratio
── one file, one tool ──────────────────
want a new tool? write one python file and drop it in ~/.rig/plugins/. no manifest, no build step, no restart. if the model writes one itself, it waits in pending until you say yes.

DESCRIPTION = "report host uptime, terse"
SCHEMA = {"type": "object", "properties": {}}
def run(args: dict) -> str:
s = open("/proc/uptime").read().split()[0]
return f"up {int(float(s) // 3600)}h {int(float(s) // 60) % 60:02d}m"
